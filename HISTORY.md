## 2026-09-03 — старт проекта

**Что это.** Григорий впервые пошёл к тренеру (Никита) после ~10 лет самостоятельных занятий по видео Овчарова. Разобрали первую тренировку, собрали программу A/B/C, решили строить свою PWA-платформу: программа + дневник в один тап + техника упражнений.

**Находки по методу (детали — `context/02`):**

- Школа Никиты имеет первоисточник — Doug Brignole, «The Physics of Resistance Exercise». Русскоязычный носитель — BIOMACHINE / **Роман Овчаров** (не Замятин — тот ведущий, не автор канала). Западный аналог глубже — N1 Education / Kassem Hanson.
- Слабое место метода — укороченная амплитуда. Метаанализ до февраля 2025: длинная позиция > короткой (ES 0,283, p 0,036). Оставили короткую только на дельтах и трицепсе, где она биомеханически оправдана.
- Главная дыра комплекса Никиты: при холке и завёрнутых плечах он выключил среднюю/нижнюю трапецию во всех девяти упражнениях. Добавлены тяга со сведением лопаток, face pull, Y-подъём.
- Скручивания при протрузии убрали (McGill: повторная флексия = механизм грыжи, ~3300 Н на диск). Замена — анти-сгибание/анти-ротация: dead bug, боковая планка, pallof press.
- Объём BIOMACHINE (4 подхода/группу/неделю) — спорный, консенсус 10–20. Биомеханика подбора и объём — разные вопросы, доверие с одного на другое не переносить.

**Решения по платформе (детали — `context/04`):**

- Самое сложное — не код, а UX ввода в зале: один тап, ноль клавиатуры, офлайн. На этом умирают все самодельные трекеры.
- Дорогая ошибка модели данных: `set_log` должен ссылаться на `exercise_id`, а не на слот программы. Программа версионируется.
- Не нужен банк на 1324 упражнения — нужно 27 (столько в программе). Банк «на будущее» = грабля Григория.

**Открытый вопрос, который заблокирует деплой:** тренируется ли Григорий в РФ (если да — не Vercel, душит РКН). К разработке этапов 0–4 отношения не имеет.

**Артефакт с разбором:** https://claude.ai/code/artifact/7f633e0a-04c1-446c-8386-ce8c3a2e2928 — «Рабочая амплитуда». Исходник — `context/artefakt-rabochaya-amplituda.html`.

## 2026-09-03 — разворот: бэкенд первым

Григорий выкинул из корневого CLAUDE.md строку про «накапливает папки, не строить на будущее» — переписал «известную слабость» на «боится провалов, подолгу отклоняет предложения». То есть мой дважды повторённый «это преждевременно» читался как стена, которую он должен пробивать. Снял это.

На вопрос «что дальше» выбрал **бэкенд первым** (не ядро тренировок, не Тело). Логика — фундамент под систему здоровья сразу, чтобы не строить хранилище дважды.

**Бэкенд: сначала Supabase, потом переиграли на Neon.** Григорий: Supabase на free засыпает на 7 дней, будится руками. Neon уходит в ноль при простое, но просыпается сам за ~0.5 сек — для local-first (синк фоновый, не на горячем пути) это решает вопрос.

Цена обмена: Supabase давал auth + storage + client SDK с RLS. Neon — только Postgres. Значит свой тонкий API-слой на Vercel Functions (`api/*`) + простой вход по коду (`APP_TOKEN` в env, вводится один раз). Для системы с агентами API-слой всё равно был бы нужен.

**Сделано:**
- `plans/02-backend-neon.md`.
- `src/server/schema.ts` — Drizzle-схема, зеркало Dexie. Время везде `bigint` epoch ms — как в клиенте, без конвертации TZ. `updated_at` + `deleted` на каждой таблице для синка. Без `user_id` — один пользователь.
- `src/server/migrations/0000_init.sql` — сгенерирована `drizzle-kit`.
- `src/server/db.ts` — Neon через `@neondatabase/serverless` (HTTP).
- `drizzle.config.ts`, `api/tsconfig.json` (серверный код исключён из клиентского билда), скрипты `db:*`.
- Supabase-код и зависимость удалены.

**Решение:** программу v1 в Postgres отдельным сидом НЕ заливаем. Её создаёт клиент (`seedIfNeeded`), push-синк уносит наверх при первом соединении. Один путь сидинга.

**Порядок:** план 02 (бэкенд) → возврат в план 01 на 1.3 + этап 2.

2. Серверный код лежал в `src/server/` — cross-dir импорт из `api/`. Перенёс в `api/_lib/` (schema, db, migrations). Не помогло.
3. **Корень:** `"type":"module"` + Vercel компилит `api/*.ts`→`.js`, но относительные импорты без расширения ESM-Node в проде не резолвит (`Cannot find module '/var/task/api/_lib/db'`). Локально tsx/vite прощают. Фикс — `.js` в относительных импортах серверного кода: `import ... from "./_lib/db.js"`.
4. Диагностировал через временный `api/ping.ts` (без импортов — поднялся) + `try/catch`, возвращающий `e.message`. Vercel CLI нет, логи иначе не видны.

Серверные скрипты (`dev-api`, `test-sync`) переведены на `.ts` + `tsx` (extensionless-резолв, не требует расширений в путях).

**Прод работает:** `/api/sync` тянет 26 упражнений из Neon; `npm run shot -- <prod>` — задеплоенный клиент показывает «сохранено».
