# Дальний горизонт — куда это растёт

**Дата:** 2026-09-03. Это запись намерения, а не план работ. Ничего из описанного здесь сейчас не строится (см. CLAUDE.md: не плодить структуру на будущее). Документ нужен, чтобы решения по MVP не загоняли в угол то, что будет потом.

## Видение

Не трекер тренировок, а **личная система здоровья**. Тренировки — первый модуль и повод начать.

Со временем внутри:

- **Хранилище всех медицинских материалов Григория за жизнь** — анализы крови, биохимия, гормоны, заключения врачей, УЗИ, выписки. Загружается по ходу жизни, накапливается, не теряется.
- **Агентная система** (референс — система друга): несколько агентов под свои задачи — диагност (парсит анализы, ищет отклонения и связи), нутрициолог, терапевт (общая картина), эндокринолог, фармаколог (совместимость добавок), сомнолог (данные носимых устройств), персональный тренер. Ценность — в том, что агенты видят **всё вместе** и ловят связи, которые теряются, когда каждый врач смотрит свою узкую зону.
- **Тренировочный модуль** как источник одного из потоков данных для этих агентов: нагрузка, прогрессия, самочувствие, ограничения (протрузия).

## Что это значит для решений сейчас

**Держать, потому что дёшево и по делу:**

- Чистая, разделённая модель данных (уже так: `exercise` / `programSlot` / `session` / `setLog`, версионирование, прямые ссылки). Агентам потом нужны честные данные, а не распутывание.
- Полный экспорт в JSON (этап 3). Это и есть реальная страховка переносимости — не абстрактная «расширяемость».
- Главный экран — хаб, а не один экран тренировки. Новые модули = новые карточки, без переписывания.
- Раздел «Тело» в навигации как якорь: сюда потом сядут замеры, а позже — документы и анализы.

**Не делать:**

- Пустые таблицы `document`, `biomarker`, `agent_note` «на вырост».
- Дашборд с виджетами до того, как появятся данные для них.
- Каркас агентов, интеграции с носимыми устройствами, загрузку PDF — пока нет ни одного реального пользовательского сценария.

## Единственное решение, которое придётся пересмотреть

**Где живут данные.** Сейчас — только IndexedDB в браузере телефона (офлайн-first, оправдано для зала). Но система здоровья с документами и облачными агентами потребует:

- доступ с нескольких устройств;
- надёжный бэкап (не «не забудь выгрузить JSON»);
- чтение данных фоновым процессом-агентом.

Это бэкенд (Supabase / своя БД + API). Переход «локально → локально + синк» заложен как нормальный путь: добавляем синхронизацию, когда появляется второе устройство или первый агент. **Строить бэкенд сейчас под несуществующие данные — дороже, чем добавить его потом.**

## Порядок, если по-крупному

1. Тренировочный MVP: программа + дневник в один тап (план 01).
2. Реальное использование, стабилизация того, что бесит.
3. Раздел «Тело»: замеры, самочувствие, вес.
4. Бэкенд + синк (триггер — второе устройство или готовность к агентам).
5. Хранилище документов: загрузка анализов и заключений, распознавание.
6. Первый агент — скорее всего диагност по анализам.
7. Остальные агенты и связи между потоками.
